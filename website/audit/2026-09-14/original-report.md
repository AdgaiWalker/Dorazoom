# DoraZoom 官网审查

日期：2026-09-14。审查对象：本地 `website/dist`，通过 `http://127.0.0.1:4277/` 实际运行。

结论：桌面视觉层级清楚，圈画、生成和保存图片可用；作为引导用户获取 Mac 应用的官网，下载状态、手机体验和辅助文字可读性仍需改进。发现 1 项 P1、5 项 P2。此次是审查，未修改网站或发布配置。

## 范围与验收限制

- 用户指定 design-qa。该技能要求设计稿与实现对照；项目内未找到官网设计稿、Figma 或已批准的视觉目标，因此遵循技能路由，完成实际页面的 UX / 设计 / 可访问性审查。
- source visual truth path：缺失。不能把当前网站、宣传视频帧或本次截图当作已批准设计稿，也没有进行虚构的保真度对照。
- 正式域名 `https://product.iwalk.pro` 在当前环境中浏览器返回 `ERR_CONNECTION_CLOSED`，独立 HTTPS 请求也未成功。仅证明本次访问失败，不能断言所有访客都无法访问，也不能断言本地与线上版本相同。
- 捕获工具：内置 Browser 打开线上地址失败、错误页无法继续控制后，使用 ego-browser 检查本地实现。
- 视口：桌面 1440 × 1000 CSS px；手机 390 × 844 和 320 × 844 CSS px；deviceScaleFactor 均为 1，截图像素与 CSS 视口相同，无密度缩放。手机为 Chromium 模拟视口，不是真机 Safari。
- state：中文、默认浅色、未登录；初始、生成后、场景选择、视频播放、FAQ 展开等状态。
- implementation screenshot path：`website/audit/2026-09-14/`，见下方逐步证据。
- full-view comparison evidence：缺少 source，未执行来源与实现的全视图比较。逐屏截图仅作为体验审查证据。
- focused region comparison evidence：缺少 source，未执行保真度局部比较；已检查画布、工具栏、文字标签、下载说明等局部区域并测量样式。

## Findings

### [P1] 获取应用的路径没有可执行终点

位置：首屏、`.nav-cta`、`#get-started`、下载 FAQ。

证据：步骤 1、7、8。首屏只有“动手圈一下”和视频；“认识 DoraZoom”跳到页尾后，仍只有“再画一个想法”和“观看完整演示”。“正式下载入口即将开放”在页尾 12px 说明和 FAQ 中才出现，没有下载或后续获取入口。

影响：有安装意愿的访客完成浏览后只能重新体验或离开。此评级基于官网承担获取应用入口的目的；如明确只作为临时演示页，可下调为 P2，但仍应提早说明状态。

修复：首屏动作附近明确写“Mac 应用即将开放下载，目前可体验网页演示”。有经过确认的发布地址时设置真正的下载主按钮；发布前可链接既有更新渠道。不要捏造下载地址或未经规划就接入收集邮箱的表单。

### [P2] 320px 工具栏按钮超出容器

位置：`.toolbar`、`.tool-group`、`.color-group`、`#clear`。

证据：步骤 11。工具栏白色容器为 x=30–290，清空按钮区域为 x=273.5–307.5，右侧超出容器 17.5px；左端画圈图标同样挤到边界外。文档 scrollWidth=320，说明“无页面横向滚动”未捕捉到组件内部溢出。

影响：按钮与容器关系破坏，小屏触控容易误点。390px 的未选颜色按钮因 transform 缩放后只有约 22.62 × 22.62px；此处作为触控风险，未据此独立断言 WCAG 目标间距规则不合格。

修复：小屏把工具、颜色与历史操作拆成可换行分组，或两排排列；按钮设置不收缩且保持足够触控面积，颜色按钮外部用固定点击区域，内部色点缩小。重新验证 320 / 360 / 390px 下所有按钮都在容器内。

### [P2] 手机画布整体缩小，目标按钮难以辨认

位置：`#drawing-canvas`、`app.js` 的 `base()`。

证据：步骤 9、10、11。390px 下 canvas 仅 328 × 205 CSS px，却保留完整三列定价页。画布逻辑宽度 720，按钮文字 11px，最终显示约 5px；9px 辅助文字约 4.1px。320px 更小。截图可见价格数字，套餐说明与按钮文字难以阅读。

影响：核心任务要求先辨认“要改哪里”再画圈，小屏用户无法轻松读出圈选目标；高像素导出不能改善当前操作视图的实际字号。

修复：手机采用同一示例中的单卡片或局部画面，保留较大的目标按钮；或提供明确的放大查看方式并同步坐标映射。不要仅提高 canvas 像素密度。保留键盘示例入口。

### [P2] 多处功能性辅助文字对比度不足

位置：`.prompt-pane label`、`.canvas-instruction`、`.demo-disclaimer`、未选中的 `.scene-tab`、`.closing-inner > p`。

证据：步骤 2、4、7、10、12，按当前浏览器计算颜色与对应纯色背景计算：

| 元素 | 字号 | 前景 / 背景 | 对比度 |
| --- | --- | --- | --- |
| 补充你的想法 | 14px | #8b8f98 / #ffffff | 3.24:1 |
| 拖动画一个圈 | 12px | #a5a7af / #f4f5f7 | 2.20:1 |
| 体验边界说明 | 12px | #818895 / #ffffff | 3.57:1 |
| 未选场景标签 | 14px | #9599a3 / #f7f8fa | 2.68:1 |
| 下载状态说明 | 12px | #7a7d86 / #202124 | 3.91:1 |

影响：操作指引、可切换场景、产品边界和下载状态都属于应能读清的内容；这些正常大小文字低于 4.5:1 目标。首屏是渐变背景，未用简化背景计算值作精确结论。

修复：集中调整支持文字 token；浅色面上可从 #626975 起步，深色面上可从 #a5aab5 起步，最终逐面重新计算。装饰性编号可保留弱化，操作说明与可点击标签不能一起弱化。

### [P2] 示例价格比“这是示例”的提示更醒目

位置：画布三列套餐、示例底部说明。

证据：步骤 2、10。画布突出 ¥0、¥29、¥99 / 月，以及“开始试用”；边界提示位于底部，以逻辑 9px、#c0c4cc 显示。外部标题只写“DoraZoom Playground / 浏览器交互体验”，没有直接说明这些不是 DoraZoom 售价。

影响：存在把演示内容理解成产品套餐和订阅价格的风险。这是基于信息层级的误解风险，未做用户访谈，不能声称已观察到真实用户误购。

修复：在画布外放置正常字号的“以下为虚构网页，仅用于圈画演示，不代表 DoraZoom 定价”；更好的长期选择是用不含价格的反馈示例。

### [P2] 三步教程省略了生成截图的操作

位置：`#workflow .step` 第三步。

证据：步骤 6。第一步给出 Control + 2，第三步视觉只显示 Command + V；正文写“截图到剪贴板后，直接粘贴”，但没有解释如何截图。仓库 README 的快捷键表列明 Control + 6 为截图到剪贴板。

影响：新用户可能在圈画后直接粘贴，却不知道缺少哪一步。未启动 Mac 应用验证该流程，结论仅针对官网教程的信息缺口。

修复：第三步明确写“按 Control + 6 截图，再按 Command + V 粘贴”，并对应调整视觉说明；更新前与当前发行版快捷键核对。
